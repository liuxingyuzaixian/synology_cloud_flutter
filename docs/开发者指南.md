## 〇、素材目录约定（26.11.06 起）

抓包、参考截图、临时素材一律放在仓库**外面**的兄弟目录，不再进 Flutter 工程：

```
synology_cloud/
├── resource/                 ← 抓包 har、参考截图、临时素材（以后都往这里放）
│   ├── Docker.har            ← 容器 Container get/list/stats 的真实响应
│   ├── 镜像详情.har          ← Image list/delete、Image get（本机返回 114，不可用）
│   ├── 记事本.har            ← NoteStation Note/Notebook/Todo/Tag/Shortcut
│   └── 截图/                 ← 对照截图（晖云 4 张容器详情 + 我们 4 张 + 镜像 2 张）
├── synology_cloud_flutter/   ← App 本体
└── nas-license-server/       ← 后端（付费权益设计文档在它的 docs/ 下）
```

规则：

1. **代码注释里引用抓包，只写日期与结论，不写 har 文件路径**。原始 har 会被清理或改名，
   路径写进注释就等于埋一个悬空引用（26.11.06 清理瘦身时就一次性冲掉了 6 处
   `otherProject/...` 的证据注释，接口结论本身没丢，但别人再想复核就没有原始文件了）。
   要留证据就把关键字段抄进注释，像 `dockerPower` 那样把 5 次写操作的请求形态列全。
2. 付费权益的设计文档在 `../nas-license-server/docs/付费权益系统设计方案.md`，
   App 侧引用它请带 `../nas-license-server/` 前缀。
3. 旧的参考工程 `otherProject/`（dsm_helper、晖云方舟抓包与截图、fnOS 参考图 appUI、
   music/video 调研素材）**已于 26.11.06 清理**，本文档第二章与
   `docs/ui_redesign/*.md` 里指向它们的行号不再可复核，只作为「当初是照着谁写的」的说明。

### 1.4 核心架构

#### 网络层
- `DsmApi`（单例）：封装所有 DSM Web API 调用，管理会话（sid/cookie），处理 119 会话失效
- `ApiClient`：通用后端请求，支持代理配置
- 请求流程：页面调用 `DsmApi().xxx()` → 内部构造参数 → `post()/get()` → 解析响应

#### 路由
- `FlyRouter` 管理全局路由
- `LoginInterceptor` 检查 `DsmApi().sid`，为空时重定向到 `/login`
- 主要路由：`/login`、主页（底部 Tab）

#### 页面导航
- `MainTabPage`：底部 5 个 Tab（首页、文件、照片、控制面板、我的）
- 使用 `IndexedStack` 保持各 Tab 状态
- `PopScope` 处理 Android 物理返回键（多选模式优先退出选择）

#### 持久化配置
- `AppPreferences`：封装 `SharedPreferences`
- 关键键：`sid`、`smid`、`host`、`port`、`account`、`password`、`servers`、`darkMode`、`webview_entries`

### 1.5 构建与部署

```bash
# 安装依赖
flutter pub get

# 运行调试
flutter run

# 构建 APK（只打 arm64，必须带 --target-platform，否则三架构全进包）
flutter build apk --release --target-platform android-arm64

# 构建 iOS
flutter build ios --release
```

> 注意：不使用 `--split-per-abi`（会导致 versionCode = ABI_CODE * 1000 + BUILD_NUMBER 的偏移）。单 arm64 依赖命令行 `--target-platform android-arm64`，gradle 的 `ndk.abiFilters` 会被 Flutter 插件追加的目标平台覆盖，单独配置不生效。

## 四、开发注意事项

### 4.1 新增 DSM 接口
1. 在 `DsmApi` 中添加方法，构造参数 Map
2. 调用 `post()` 或 `get()` 方法
3. 在调用处处理 `data`/`result` 字段
4. 注意 `error.code == 119` 表示会话失效

### 4.2 自适应尺寸
- 使用 `.r`、`.h`、`.w`、`.sp` 进行尺寸适配
- 使用 `.asp`、`.aw` 进行高级适配（在 `app_adaptive.dart` 中定义）
- 在平板上需要特殊处理时使用 `MediaQuery.of(context).size.shortestSide > 600` 判断

### 4.3 页面跳转
- 新页面使用 `Navigator.push(context, MaterialPageRoute(builder: (_) => XxxPage()))`
- 全局路由使用 `FlyRouter().pushNamed(context, '/path')`
- 底部 Tab 页面使用 `IndexedStack` 保持状态

### 4.4 调试
- 在"我的"页面标题连续点击 5 次（3 秒内）可激活调试模式
- 调试悬浮按钮出现后可跳转调试页面
- 调试页面可设置代理、查看 API 请求等

### 4.5 构建
- 打包命令 `flutter build apk --release`，不使用 `--split-per-abi`；arm64-only 由 gradle `ndk.abiFilters` 控制
- 版本号格式：`0.0.x+y`（x 为版本号，y 为构建号），打包/运行/更新 JSON 三处 versionCode 完全一致

### 4.6 全局默认 UI 样式约定（新功能默认照此实现，无需每次单独指定）

| 场景 | 默认组件 / 约定 | 位置 | 说明 |
| --- | --- | --- | --- |
| 页面滚动体 | `CustomScrollBar(controller, child)` 直接包裹滚动控件 | `components/CustomScrollBar.dart` | 新列表页默认套这层药丸快滚条；controller 必须与滚动控件共用。需要下拉刷新再外加 `AppRefresh`。不要再手写系统 `Scrollbar` |
| 下拉刷新 | `AppRefresh` | `components/app_refresh.dart` | 经典样式：↓箭头 + 「下拉刷新/松开刷新/刷新中…」+ 最后更新时间 |
| 快速滚动条 | `CustomScrollBar` | `components/CustomScrollBar.dart` | 26.5×44 白药丸（内上下**实心三角**、两三角间距 4，箭头色 #333333，复刻系统相册；描边折角和 6px 细条都被退回过，33 高因"太圆"被否），距列表右边 12，滚动时出现、1.5s 淡出，可拖动按比例定位；尺寸为固定逻辑像素，Pad/横屏不放大 |
| 轻提示 | `AppDialog.toast(msg)` | `components/app_dialog.dart` | 全局 Toast，禁止再用 `ScaffoldMessenger.showSnackBar` |

| 二次确认 | `AppDialog.confirm(...)` | 同上 | 统一确认弹窗，返回 `Future<bool>` |
| 文本输入弹窗 | `FnInputDialog` | `components/fn_input_dialog.dart` | 重命名/新建等单行输入统一使用 |
| 应用宫格分组 | `AppSectionGrid` + `AppSectionItem` | `components/app_section.dart` | 首页/设置类「上标题 + 下方块宫格」统一样式 |
| **下拉选择（唯一口径）** | `FnDropdownPicker<T>` + `FnDropdownOption<T>` | `components/fn_dropdown_picker.dart` | 26.11.01 反馈「下拉 tab 不一样，用我们自己首页的，做成通用的，以后所有的都默认用这个」——**所有「点一下弹出菜单选一项」的场景一律用它**，禁止再在页面里裸写 `PopupMenuButton` 自造样式。两档：`FnDropdownSize.pill`（卡头排序/筛选，首页进程卡同款）、`.title`（顶栏页面标题，资源监控页六个分类）。弹层固定 `PopupMenuPosition.under` + `Offset(0,6)` + 14r 描边圆角，当前项主色加粗 + 对勾 |
| **分段切换（唯一口径）** | `FnSegmented<T>` + `FnSegItem<T>` | `components/fn_segmented.dart` | 同一屏内 2–4 个互斥视图（记事本笔记/待办、资源监控进程/服务）用它，浅灰槽 + 选中白卡带阴影、160ms 形变。计数由调用方拼进 `label`（如「服务 (27)」），组件不猜业务字段、也不因 0 自己删括号。**不要再手写一排 `Container` 当 tab** |

| 尺寸适配 | `.w/.h/.r/.asp/.aw` | `flutter_screenutil` + `utils/app_adaptive.dart` | 所有间距/字号必须适配，禁止裸写固定 px |
| 颜色与深色模式 | 全局 `ThemeData`（`app.dart`，跟随系统 light/dark） | `lib/app.dart` | 普通页面取 `Theme.of(context)`，**禁止写死浅色 `Color(0xFF...)`**；音乐库用 `context.mcXxx`（`music_theme.dart`），视频库用 `context.vcXxx`（`video_theme.dart`）；全屏播放器/悬浮条为固定深色设计属例外 |
