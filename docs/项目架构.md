# Synology Cloud — 项目架构说明

本文件总结了当前仓库的结构、页面路由、网络/接口层、持久化配置、重要关联关系和运行时行为，便于后续维护。

## 项目结构概览
- `lib/main.dart`：应用入口，初始化 `AppPreferences`、`DebugTools`、恢复会话并注册路由。
- `lib/app.dart`：全局 `MaterialApp` 配置、主题切换、`FlyRouter` 导航、全局调试悬浮按钮覆盖层。
- `lib/routes.dart`：路由表和拦截器管理。
- `lib/core/router/fly_router.dart`：路由注册与跳转、路由拦截器实现。
- `lib/core/network/dsm_api.dart`：DSM Web API 封装，负责 Synology DSM Web API 请求与会话管理。
- `lib/core/network/api_client.dart`：通用后端请求客户端，负责 token 头、通用响应验证和代理配置。
- `lib/core/storage/app_preferences.dart`：`SharedPreferences` 封装层，统一读取/写入持久化配置。
- `lib/pages/*`：各功能页面与模块实现，如登录、设置、首页、文件、相册、调试等。
- `lib/core/ui/*`：公共 UI 组件、对话框、提示、悬浮按钮等。

## 主要路由与页面
路由由 `lib/routes.dart` 注册，关键入口如下：

- `/login` → `lib/pages/login/login_page.dart`：登录流程与服务器选择。
- 主底部导航页 → `lib/pages/main/main_tab_page.dart`。
- `/debug` → `lib/pages/debug/debug_page.dart`：调试页面。
- `/image-preview` → `lib/pages/image/image_preview_page.dart`：图片/视频预览页面。
- `/photos` → `lib/pages/photos/photos_page.dart`：相册页面。
- `/settings`（“我的”）→ `lib/pages/settings/settings_page.dart`：设置页面。

此外，`LoginInterceptor` 会检查 `DsmApi().sid`，若为空则重定向到 `/login`。

## 网络 / 接口层
当前项目有两条主要网络通道：

### 1. `DsmApi`（`lib/core/network/dsm_api.dart`）
这是 Synology DSM Web API 的核心封装层，负责：

- 构造 `Dio` 请求
- 管理当前服务器信息、会话 ID、Cookie
- 执行 DSM Web API 调用
- 处理通用错误与会话失效

#### 核心行为
- `login(...)`：调用 `auth.cgi` 登录 DSM。
- `logout()`：调用 `auth.cgi` 注销登录。
- `fileList(...)`：调用 `entry.cgi` 获取文件列表。
- `dashboardData()`：批量请求 DSM 仪表盘数据。
- 相册相关接口：`fotoTimeline`, `fotoAlbums`, `fotoThumbnailUrl`, `fotoDownloadUrl`, `fotoTeamThumbnailUrl` 等。
- 下载站接口：`downloadTaskCreate`, `downloadTaskAction` 等。

#### 响应与会话处理
- `_parseResponse()` 会尝试将字符串 JSON 解析为对象。
- 若响应中包含 `error.code == 119`，则视为会话失效。
- 会话失效由 `_handleLogout()` 统一处理：清空 `_sid`、`_cookie`、`_server`，移除 `sid`/`smid`，并跳转 `/login`。

#### 代理与 TLS
- `_createDio()` 每次请求都会创建一个新的 `Dio` 实例。
- 当 `checkSsl` 为 false 时，会跳过 HTTPS 证书校验。
- 代理配置来自 `AppPreferences`：`debugIpSwitch`, `debugIp`, `debugPort`。
- 代理设置已修改为在所有构建模式下生效，不再仅限于 debug 模式。

### 2. `ApiClient`（`lib/core/network/api_client.dart`）
这是通用后端请求客户端，主要负责：

- 统一 `Dio` 配置
- token 头与 `Cookie` 设置
- 集中处理状态码与错误信息
- 读取并应用代理配置

#### 主要逻辑
- `saveProxy(enabled, host, port)`：保存代理配置并立即应用。
- `applySavedProxy()`：读取代理配置，全局设置 `IOHttpClientAdapter` 代理。
- `request(...)`：执行请求、校验响应、解析 `data`/`result` 字段。
- `validateResponse(...)`：当返回体包含 `code` 时，允许 `8000`、`0`、`200` 为成功；否则抛出 `ApiError`。

## 常见 API 响应格式
- DSM Web API 通常返回：
  - 成功：`{ "success": true, "data": { ... } }` 或 `{ "data": { ... }, "success": true }`。
  - 错误：`{ "error": { "code": 119 }, "success": false }`。
- 其他通用后端接口通常返回：`{ code: 0, data: { ... } }` 或 `{ code: 8000, result: [...] }`。

## 持久化配置键
常用的 `AppPreferences` 键包括：
- `host`, `port`, `base_url`：DSM 服务地址。
- `account`, `password`, `note`：账号信息与备注。
- `sid`：DSM 登录会话 ID。
- `smid`：DSM Cookie 字符串。
- `https`, `check_ssl`：传输与证书校验设置。
- `servers`, `webview_entries`：服务器列表和自定义页面列表。
- `debugIpSwitch`, `debugIp`, `debugPort`：手动代理设置。
- `authToken`：通用后端认证 token。
- `darkMode`：深色模式开关。
- `debug_button_enabled`：调试悬浮按钮启用状态。

## 关键运行时关联
- `main.dart` 先初始化 `AppPreferences`，再初始化 `DebugTools`，最后调用 `DsmApi()` 并恢复会话。
- `_restoreSession()` 会从已保存配置构建 `ServerModel`，并调用 `DsmApi().setServer(...)` 与 `DsmApi().setSession(...)`。
- 由于路由拦截器依赖 `DsmApi().sid`，因此必须在 `runApp()` 之前恢复会话。
- `DsmApi` 是当前 DSM 会话的单例源，当前会话状态由 `_sid` 和 `_cookie` 维护。
- 119 会话失效错误在 `DsmApi._checkAuthError()` 内统一处理。
- 代理配置由 `DsmApi` 与 `ApiClient` 双向读取，保证 DSM 与通用后端都可使用手动代理。

## DsmApi 主要接口速查
| 方法 | 功能 | 关键参数 | 说明 |
|---|---|---|---|
| `login(...)` | DSM 登录 | `account`, `password`, `otpCode`, `host`, `cookie` | 调用 `auth.cgi` 登录并保存 Cookie |
| `logout()` | 注销登录 | 无 | 调用 `auth.cgi?api=SYNO.API.Auth&method=logout` |
| `queryApis()` | 查询可用 API | 无 | 调用 `query.cgi` 查询 DSM 接口目录 |
| `fileList(path, ...)` | 获取文件列表 | `path`, `sortBy`, `sortDirection` | `SYNO.FileStation.List` 文件列表 |
| `createFolder(path, name)` | 创建文件夹 | `path`, `name` | `SYNO.FileStation.CreateFolder` |
| `rename(path, name)` | 重命名 | `path`, `name` | `SYNO.FileStation.Rename` |
| `deleteTask(paths)` | 删除文件 | `paths` | 异步删除任务 |
| `copyMoveTask(paths, dest, removeSrc)` | 复制/移动 | `paths`, `dest`, `removeSrc` | `SYNO.FileStation.CopyMove` |
| `searchTask(paths, pattern, recursive)` | 搜索文件 | `paths`, `pattern`, `recursive` | `SYNO.FileStation.Search` |
| `fotoTimeline(...)` | 相册时间线 | `offset`, `limit` | 返回照片时间线数据 |
| `fotoAlbums(...)` | 相册列表 | `offset`, `limit` | 返回 DSM Foto 相册 |
| `fotoThumbnailUrl(itemId, size, cacheKey)` | 缩略图 URL | `itemId`, `size`, `cacheKey` | 构造缩略图访问链接 |
| `fotoDownloadUrl(itemId)` | 下载链接 | `itemId` | 构造照片下载链接 |
| `downloadTaskCreate(...)` | 创建下载任务 | `url`, `type`, `filePath` | DownloadStation 任务创建 |

> 说明：若接口返回 `data` 或 `result`，调用方通常直接读取其中业务字段。

## 调试悬浮按钮行为
- 全局调试悬浮按钮由 `lib/app.dart` 中的 `_GlobalOverlay` 控制，绑定 `DebugTools.debugButtonNotifier`。
- 启用后会显示 `SuspensionButton`，点击跳转 `DebugPage`。
- `lib/core/debug/debug_tools.dart` 提供：
  - `init()`：启动时读取 `debug_button_enabled`。
  - `activate()`：启用调试按钮并弹出提示。
  - `activateAndOpen()`：启用调试按钮并打开调试页面。
  - `disableDebugButton()`：禁用调试按钮。
- `SettingsPage` 中“我的”标题的隐藏激活逻辑为：3 秒内连续点击 5 次将触发 `DebugTools.activate()`，仅启用按钮而不自动跳转。
- 下次启动应用时，若 `debug_button_enabled` 为 true，调试按钮会自动显示。

## 图片预览与实况照片检测
### 实况 / 动态图片识别
- `lib/pages/photos/models/foto_photo.dart` 中的 `FotoPhoto.isLivePhoto` 已改进。
- 判定逻辑为：
  - 如果存在 `livePhotoVideoId`，则视为实况照片；
  - 否则根据文件后缀判断：`heic`, `heif`, `gif`, `apng`, `webp` 均视为动态/实况图片。
- 这修复了动态 PNG、GIF 和 WebP 未被识别的问题。

### 图片详情预览 UX
- `lib/pages/image/image_preview_page.dart` 区分静态图片和动画图片：
  - 对于动画图片，使用 `PhotoView.customChild()` 直接展示 `CachedNetworkImage`，保留动画效果；
  - 对于静态图片，使用 `PhotoView(imageProvider: CachedNetworkImageProvider(...))`，提供更好的缩放体验。
- 加载占位 UI 显示缩略图与进度指示器，失败时显示底色断裂图标。
- 预览页支持：
  - 垂直下拉退出；
  - 左右滑动切换图片；
  - 视频页点击加载并自动播放；
  - 下载进度显示与取消。

## 维护建议
- 新增 DSM 功能时优先在 `DsmApi` 中封装接口，避免将 DSM 请求散落在页面层。
- 对于非 DSM 后端请求，统一使用 `ApiClient.request()` 并保持响应校验一致。
- 代理配置不生效时，先确认 `AppPreferences` 中保存了 `debugIpSwitch`, `debugIp`, `debugPort`，并在必要时调用 `ApiClient().applySavedProxy()` 或重启应用。
- 会话失效时，优先检查是否出现 DSM 错误码 `119`。
- 隐藏调试按钮激活当前仅启用按钮，不会自动打开调试页。

## 完整 DSM 接口列表（方法 & 请求参数字段表）

> 下面列出 `lib/core/network/dsm_api.dart` 中常用的 DSM API 封装方法，包含简要说明、调用的 DSM CGI（`auth.cgi`/`entry.cgi`/`query.cgi` 等）、以及最常用的请求参数字段与返回关键字段。此表旨在帮助前端开发快速理解每个方法需要的参数。

### 通用字段说明
- `api`: DSM 接口名称（例如 `SYNO.API.Auth`、`SYNO.FileStation.List`）
- `method`: 接口方法（`login`、`logout`、`list`、`create` 等）
- `version`: 接口版本号（通常为 `1` 或 `2`）
- `_sid` / `session`: 会话 ID（登录后来自 `auth.cgi` 的 `sid`）

### 接口明细

- 方法: `login`
  - CGI: `auth.cgi`
  - 关键参数: `account`, `passwd`, `otp_code` (可选), `enable_device_token` (可选)
  - 返回字段: `data.sid`, `data.sessInfo`, `data.cookie` (或 Cookie header)

- 方法: `logout`
  - CGI: `auth.cgi`
  - 关键参数: `session`(sid)，`format=json`
  - 返回字段: `success`

- 方法: `queryApis`
  - CGI: `query.cgi`
  - 关键参数: 无
  - 返回字段: `data.apis[]`（每项含 `name`, `path`, `maxVersion` 等）

- 方法: `fileList` / `listFolder`
  - CGI: 一般通过 `entry.cgi` 调用 `SYNO.FileStation.List`
  - 关键参数: `folder_path`/`path`, `limit`, `offset`, `sort_by`, `sort_direction`, `additional`(如 `owner,perm`)
  - 返回字段: `data.files[]`（每项含 `name`, `path`, `size`, `isdir`, `filetype`）

- 方法: `createFolder`
  - CGI: `entry.cgi` -> `SYNO.FileStation.CreateFolder`
  - 关键参数: `path`, `name`
  - 返回字段: `success`, `data.folder`（新文件夹信息）

- 方法: `rename`
  - CGI: `entry.cgi` -> `SYNO.FileStation.Rename`
  - 关键参数: `path`, `name`
  - 返回字段: `success`, `data`（任务结果）

- 方法: `copyMoveTask`
  - CGI: `entry.cgi` -> `SYNO.FileStation.CopyMove`
  - 关键参数: `paths[]`, `destination`, `remove_src` (0/1)
  - 返回字段: `data.jobs[]`（异步任务 id / 状态）

- 方法: `deleteTask`
  - CGI: `entry.cgi` -> `SYNO.FileStation.Delete`
  - 关键参数: `paths[]`
  - 返回字段: `data.jobs[]`

- 方法: `searchTask`
  - CGI: `entry.cgi` -> `SYNO.FileStation.Search`
  - 关键参数: `folder_path`/`paths[]`, `pattern`, `recursive`, `limit`, `offset`
  - 返回字段: `data.files[]`

- 方法: `fotoTimeline`
  - CGI: `entry.cgi` / Foto API
  - 关键参数: `offset`, `limit`, `start_time`, `end_time`, `filter`
  - 返回字段: `data.items[]`（照片项，含 `id`, `time`, `album_id` 等）

- 方法: `fotoAlbums`
  - CGI: Foto 专用 (通常为 `entry.cgi` 下的 Foto API)
  - 关键参数: `offset`, `limit`, `sort`
  - 返回字段: `data.albums[]`（`id`, `title`, `thumbnail_id`, `count`）

- 方法: `fotoThumbnailUrl`
  - CGI: 构造访问 `photo/thumbnail` 或 `foto/thumbnail` 的 URL
  - 关键参数: `id`/`itemId`, `size`, `cache_key`
  - 返回字段: 无（返回直接可访问 URL）

- 方法: `fotoDownloadUrl`
  - CGI: 构造下载 URL
  - 关键参数: `itemId`, `filename` (可选)

- 方法: `downloadTaskCreate`
  - CGI: DownloadStation（`entry.cgi` 或 `download.cgi`）
  - 关键参数: `uri`/`urls[]`, `destination`, `username`, `password` (下载站任务相关)
  - 返回字段: `data.task_id`, `success`

- 方法: `downloadTaskAction`
  - CGI: DownloadStation
  - 关键参数: `task_ids[]`, `action` (`pause`, `resume`, `delete`)

- 方法: `systemInfo`, `utilization`, `dashboardData`
  - CGI: `entry.cgi` / 各类 `SYNO.API` 接口
  - 关键参数: 视具体 API 而定，通常为 `api`, `method`, `version`
  - 返回字段: `data`（CPU/内存/磁盘使用、服务状态等）

> 注：上述方法对应的具体实现可能会根据 DSM 版本和系统插件差异有所变化，建议在调用前使用 `queryApis()` 或查阅 DSM API 文档确认 `api` 名称与参数。

### 如何快速为新 DSM 接口添加封装
1. 在 `DsmApi` 中添加方法名并实现：构造参数 Map（包含 `api` / `method` / `version`）并调用内部 `_request()` 或 `_post()`。
2. 在调用处处理 `data` / `result` 字段，并针对 `error.code == 119` 不可用时抛出或处理会话失效。
3. 添加单元测试或在开发模式下通过 `queryApis()` 验证接口是否可用。
